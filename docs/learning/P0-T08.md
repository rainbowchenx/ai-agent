# P0-T08 断点笔记

日期：2026-09-06

## 学习目标

Server 是装配根：读配置 → 开 SQLite → 挂 HTTP 门面。HTTP 不写 Agent loop；P0 这一步只暴露 health / config / sessions。Model / tools / Runner 留给 Task 9 的 WebSocket run。

## 我亲手验证过的行为

- `GET /health` → `{ ok: true, version }`（来自 `packages/server/package.json`）。
- 无 `config.yaml` 时写出 `defaultAppConfig()`；已有文件则原样加载，不覆盖。
- `PUT /config` 走 Zod：非法 400；合法写回 YAML，且不含明文 `apiKey`。
- `POST /sessions` → `{ id }`；`GET /sessions` 的 `createdAt` / `updatedAt` 是 ISO 字符串。
- `GET /sessions/:id` 带回 `MessageDto`（`id` + `role` + `content` + `createdAt`）；不存在则 404。
- `SqliteSessionStore.getMessages` 仍只返回 `AgentMessage`；`getMessageRows` 额外读 `messages.id` / `payload` / `created_at`。

装配顺序（P0 已落地）：config → db → sessionStore → routes。model / tools / Runner 尚未装配。

## 自问

- **为什么绑定 `127.0.0.1` 而不是 `0.0.0.0`？** 本机 Agent：只给本机 Electron / CLI 用。`0.0.0.0` 会把 8787 暴露到局域网，多一张攻击面。
- **HTTP 为什么只是门面？** Route 只做 DTO 进出和 404/400；会话记忆在 SQLite，推理在 Runner。换 UI 或加 CLI 时契约不变。

# P0-T02 断点笔记

日期：2026-09-05

## 我理解的分包理由

`@agent2026/shared` 冻结 HTTP/WS 契约与配置 Zod schema，让 Electron UI 与 Fastify Server 只通过 DTO/事件通信。换 UI 或换传输层时，只要契约不变，内核（core）无需改动。

## RunEvent：谁发、谁收

| 事件 | 发送方 | 接收方 | 含义 |
|------|--------|--------|------|
| `run_start` | Server（Runner 映射） | Desktop UI | 一次 run 开始，携带 runId / sessionId / traceId |
| `message_delta` | Server | Desktop UI | 助手文本流式片段 |
| `tool_start` | Server | Desktop UI | 工具调用开始，展示参数卡片 |
| `tool_end` | Server | Desktop UI | 工具返回结果（可标记 isError） |
| `permission_request` | Server | Desktop UI | 权限闸门需用户确认 |
| `error` | Server | Desktop UI | 本轮 run 出错（Provider/内部） |
| `run_end` | Server | Desktop UI | run 结束，reason: completed / stopped / error |

UI 上行仅 WS：`{ type: "run", sessionId, content }` 发起对话；`{ type: "permission_response", requestId, allow }` 回复权限。

## 自问：为什么 `permission_request` 要有 `requestId`？

一次 run 可能连续触发多次工具权限询问，或 UI 异步响应。`requestId` 把「某一次询问」与「用户那一次 allow/deny」精确配对，避免响应错序、重复或过期回调绑错工具。

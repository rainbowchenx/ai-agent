# P0-T07 断点笔记

日期：2026-09-06

## 学习目标

Session/Trace 是 harness 记忆；重启可恢复是「成品感」来源。消息与 span 落在 Server 的 SQLite，而不是 Electron。

## 我亲手验证过的行为

- `openSqlite` 建出 `sessions` / `messages` / `traces` / `spans`。
- `create` → `appendMessage`（user / assistant+toolCalls / tool）→ 关库再开，`get` / `getMessages` / `list` 仍在。
- `startTrace(runId, sessionId)` → 父子 `startSpan` → `endSpan(status, metadata)`，重开后行内容一致。
- 默认路径 helper：`~/.agent2026/data.sqlite`；测试走 temp 目录。
- Windows 上 `better-sqlite3@13` 用 VS2019 BuildTools + Python 3.12 本地编过，未切 sql.js。

用 `better-sqlite3` 直接读测试库：`traces.run_id` 绑一次 run；`spans.parent_span_id` 指向父 span；`messages.payload` 是整段 `AgentMessage` JSON（含 `toolCalls`）。

## 自问

- **消息存在 Server 还是 Electron？为什么？** Server。Electron 只是壳；Renderer 禁止调模型/工具。会话是 harness 记忆，必须跟 Runner / 权限 / Trace 同进程，才能重启恢复且被 CLI 等其它客户端复用。落库路径是 `~/.agent2026/data.sqlite`，由 Server 写。
- **`traceId` 与 `runId` / `sessionId` 的关系？** `sessionId` 是对话寿命（多次 run）；`runId` 是一次 `Runner.run`；`traceId` 是这次 run 的观测树根，`startTrace` 把 `runId` + `sessionId` 绑在一起，span 挂在 `traceId` 下。

## 还不懂的点

- P1 Trace 面板要不要按插入序读 span（同毫秒 `started_at` 不能当唯一序）。
- 消息是否要有独立 `id` 列对齐 `MessageDto`（当前只在 JSON payload 里）。

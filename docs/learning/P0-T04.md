## 学习目标

ReAct 循环是 Agent 的心脏：模型 →（可选）工具 → 再模型。先用 Mock `ModelPort` 把循环跑对，再接真 API。core **不依赖** `@agent2026/shared`；Runner 事件形状与 shared `RunEvent` 对齐，映射留给 server。

## 我亲手追过的一次 run

场景：Mock 第一轮 `tool_call`（echo `{ text: "ping" }`），第二轮 `text_delta`（`"pong"`）。

测试中临时 `console.log(messages.length, roles)`，再删掉。

```text
初始: []
+ userMessage
turn0: messages.length = 1  [user]
       model.stream → tool_call echo("ping")
       append assistant(tool_calls)
       messages.length = 2  [user, assistant]
tool:  execute echo → "ping"
       append tool { toolCallId, content: "ping" }
       messages.length = 3  [user, assistant, tool]
turn1: model.stream(含 tool 结果) → text_delta "pong"
       append assistant { content: "pong" }
       messages.length = 4  [user, assistant, tool, assistant]
run_end reason=completed
```

事件顺序：`run_start` → `tool_start` → `tool_end` → `message_delta` → `run_end`。

### Abort 时发生了什么

`AbortSignal` 在第一段 `text_delta` 之后被 abort。Runner 在流消费后检查 `signal.aborted`，发出 `run_end { reason: "stopped" }`，不再进入下一轮模型调用。不是 `error`：用户/调用方主动停，不是崩溃。

### 工具抛错怎么办

**不崩整个 run。** catch 成字符串写回 `role: "tool"` 的 `content`，`tool_end.isError = true`，再让模型看结果继续。见 spec 5.4。

## 自问

- **messages 如何增长？** user → assistant(tool_calls) → tool → assistant。缺 assistant(tool_calls) 或 tool 消息，下一轮模型对不上 `tool_call_id`。
- **权限闸门在哪？** `ask_all` 时先 `permission_request`，再等 `onPermissionRequest` Promise；deny 把拒绝字符串当 tool result 写回，不 execute。
- **maxTurns？** 一轮 = 一次 `model.stream` +（可选）一批工具。到上限不再开新的模型调用，`run_end reason=completed`。

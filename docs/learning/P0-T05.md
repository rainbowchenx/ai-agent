# P0-T05 断点笔记

日期：2026-09-06

## 学习目标

内置工具是「最小能力地板」；MCP 只是另一来源的 `ToolDefinition`，对 Runner 无差别。`createBuiltinToolPort` 按 config 白名单装配，`ToolRegistry` 统一 `list` / `execute`。

## 我亲手验证过的行为

### read_file

- 在 `workspaceRoot` 下写 `hello.txt`，`read_file { path: "hello.txt" }` 返回内容。
- 故意传 `../secret.txt` → 抛错 `path traversal rejected`，不会读到 workspace 外。

**为什么防路径穿越？** 模型给出的 `path` 不可信；`../` 或绝对路径若直接 `readFile`，可能读到用户 home、`.env`、SSH key。先 `normalize` + `resolve`，再校验 resolved 路径仍以 `workspaceRoot` 为前缀。

### http_fetch

- `file:///etc/passwd` → 拒绝，仅允许 `http:` / `https:`。
- mock `fetch`：响应体 `abcdefghijklmnop`，`maxChars: 5` → 只返回 `abcde` 并标记 truncated。
- 慢响应 + `timeoutMs: 50` → `request timed out`。

## 自问

- **为什么工具白名单在 config 的 `agents.default.tools.builtin`？** 不同 agent / 环境需要不同能力；P0 在配置层显式列出 `read_file` / `http_fetch`，避免模型或未审查的 MCP 默认可用写盘、任意 URL。Runner 只执行已装配进 `ToolPort` 的工具。
- **工具 schema 如何变成模型可调用的 function？** `ToolDefinition.parameters` 是 JSON Schema；Provider 在 `model.stream` 前把 `tools.list()` 映射为 OpenAI `tools[]`（`type: function`, `function: { name, description, parameters }`）。模型返回 `tool_calls` 后 Runner 按 `name` + `arguments` 调 `tools.execute`。

## 还不懂的点

- `read_file` 对符号链接指向 workspace 外的硬拦截（当前靠 resolve 后前缀检查，未单独 `lstat`）。
- 大文件 / 二进制文件的策略（P0 仅 UTF-8 文本）。

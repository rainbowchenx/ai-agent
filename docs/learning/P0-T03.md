# P0-T03 断点笔记

日期：2026-09-06

## 学习目标

Ports & Adapters：`ModelPort` / `ToolPort` 是「洞」，Provider/MCP/Sidecar 是「插头」。先定洞，再写插头。

## 默写：`ModelPort.stream` 三种事件

1. `text_delta` — 模型输出文本片段（`text: string`）
2. `tool_call` — 模型请求调用工具（`id`, `name`, `arguments`）
3. `usage` — token 用量（可选 `inputTokens` / `outputTokens`）

## 自问：为什么 core 不直接 import OpenAI SDK？

- **依赖隔离**：core 是内核，不应绑定任何具体厂商 HTTP/SSE 实现；换 Provider 只改 `packages/providers`。
- **可测试性**：Runner 可用 Mock `ModelPort` 跑通 ReAct 循环，无需网络或 API key。
- **格式统一**：内部 `AgentMessage` 与 `ModelStreamEvent` 是 canonical 形态；OpenAI/Anthropic 差异关在适配器里。

## 自问：Tool 结果为什么是 `string` 回给模型？

多数 Chat Completions API 的 `tool` role 消息 `content` 字段是**字符串**（工具输出序列化为文本再写回上下文）。Runner 统一 `Promise<string>`，适配层负责 JSON.stringify 或人类可读格式；模型侧始终收到文本块，与 OpenAI/兼容网关一致。

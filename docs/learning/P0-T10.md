# P0-T10 断点笔记

日期：2026-09-06

## 学习目标

桌面端是「宿主」：管进程生命周期，不管智能。Renderer 只通过 HTTP/WS 跟本机 Server 说话，不碰模型、不跑工具。

## DEV vs PROD 启动路径

| 模式 | Server 怎么起来 |
|------|----------------|
| DEV，8787 已健康 | **复用**已有进程（`pnpm dev` / `dev:server` 双启时走这条） |
| DEV，8787 没人听 | Main 在仓库根 spawn：`pnpm --filter @agent2026/server exec tsx src/index.ts` |
| PROD，`packages/server/dist/index.js` 存在 | spawn `node <dist>` |
| PROD，还没有 dist | **回退**到上面的 pnpm+tsx（P0 server 尚未加 `tsc` build） |

端口与 `baseUrl` 写入 Electron `userData/server.json`，preload 只暴露 `getServerBaseUrl()`。

退出时 Windows 用 `taskkill /PID <pid> /T /F` 杀进程树（pnpm → tsx → node）；Unix 对子进程 `SIGTERM`。

## 怎么验证

- 只开壳：`pnpm dev:desktop`。页面应显示 `http://127.0.0.1:8787`，Health `ok`。不必先手动开 server。
- 双启：先 `pnpm dev:server`，再 `pnpm dev:desktop`。日志应复用已有 8787，不重复 spawn。
- 单测：`pnpm --filter @agent2026/desktop test`

Windows 首次装 Electron 若 `ECONNRESET`，可设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

## 自问

**为什么 preload 要隔离，而不是在 renderer 里 `child_process`？**  
Renderer 是网页，开了 `nodeIntegration` 等于把本机文件系统和进程控制交给任意页面脚本。preload + `contextBridge` 只交出「问一下 Server 地址」这一条 IPC，模型/工具永远在 Server 进程。

**为什么 Server 崩溃可重启、退出必须杀子进程？**  
壳是守护进程。不杀树会在 Windows 上留下孤儿 `tsx`/`node` 占着 8787。

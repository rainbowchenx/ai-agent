## 2. 理念（为何记在记忆层）

严格 RSI 要求改进「改进能力」本身；工程上更稳的是 **受约束、可审计的 harness/记忆级自进化**：

```text
使用 / 探索  →  验证（环境反馈或规则）  →  沉淀进长期记忆  →  冻结复用
                                                      ↑
                                              可 diff / 可回滚 / 可检索
```

- **Scaling Experience**：参数固定时，靠经验与因果结构复利。  
- **验证优先**：没有可靠信号就写入，等于错误复利。  
- **冻结边界**：探索阶段写入候选记忆；任务执行阶段优先读冻结集，避免边跑边污染。

## 3. 两段能力（方案 4 拆解）

### 3.1 日常：任务后提炼（默认开）

| 触发 | 行为 |
|------|------|
| run / session 结束（Hooks） | 异步从轨迹提炼候选记忆 |
| 写入前 | 轻量校验（去重、冲突、最低置信/证据字段） |
| 失败 | 降级为「无新记忆」，不阻断用户对话 |

与既有规格对齐：提炼逻辑放在 **Server Hooks / 装配层**，经 MCP 调 OpenViking；`core` 不依赖 OpenViking SDK。

### 3.2 可选：新工作区轻量探索（显式触发）

| 触发 | 行为 |
|------|------|
| 用户「熟悉此项目」或首次绑定 workspace | 短预算探索（工具边界、目录约定、常见失败） |
| 形态 | 简化版 BRS（广）→ 可选短 DRS（深）；**非**完整 RSIAgent 复刻 |
| 结束 | 候选记忆经校验后 **冻结**，供后续任务检索 |

探索预算、是否默认开启 → 实现计划阶段再定数值；默认建议 **手动触发**，避免烧 token。

## 4. 记忆条目草案（实现时再 Zod 化）

倾向结构化，而非纯散文笔记：

| 字段 | 含义 |
|------|------|
| `kind` | `fact` / `procedure` / `preference` / `boundary`（名可调） |
| `when` | 适用条件 |
| `do` | 动作或结论 |
| `outcome` | 观测结果 / 证据指针（traceId、路径） |
| `confidence` | 粗置信或来源 |
| `status` | `candidate` → `frozen` / `rejected` |

便于检索、覆盖冲突条目、以及日后做「评测通过才升级为 frozen」。

---

## 5. 与现架构的咬合

```text
Runner / Session (SQLite)     ← 短期
        │ Hooks: after_run / session_end
        ▼
 Memory consolidation (Server)  ← RSI 环的「写」
        │ MemoryPort 或 MCP tools
        ▼
 OpenViking (旁路)              ← 长期
        │
 before_model 检索注入           ← RSI 环的「读」
```

设置中心可后续增加「记忆 / 探索」分区（开关、预算、清空候选）；**不**把密钥与记忆混在同一配置面。

---

## 6. 风险与纪律

| 风险 | 对策意向 |
|------|----------|
| 错误复利 | 候选与冻结分离；关键类要验证信号 |
| AGPLv3 OpenViking | 保持可选 MCP 后端；不可用则无记忆降级 |
| 成本 | 探索手动触发；提炼异步、可关 |
| 范围膨胀 | 禁止第一期自动改 Runner/权限核心逻辑 |
